# GH-0 — İnsana bırakılanlar (gh CLI ile yapılamayan ya da insan kararı gerektiren)

Durma koşulu değil; tur bunlar açıkken devam eder. Her madde bir insan adımı ya da kararıdır.

1. **"En az 1 onay (sen)" tek hesapla uygulanamaz.** Ajan ve insan aynı GitHub hesabıyla (`arknsensei`) çalışıyor; GitHub kişinin kendi PR'ını onaylamasına izin vermez. Bu yüzden "1 onay" kuralı ayrı bir ruleset'te (`25320155`) ve depo yöneticisi muafiyetiyle duruyor; bu turun PR'ları yönetici yetkisiyle (`gh pr merge --admin`) birleşir. PR zorunluluğu, zorunlu CI kontrolleri, doğrusal geçmiş ve zorla push yasağı ise muafiyetsiz ruleset'te (`25320154`): CI kırmızıyken kimse birleştiremez, `main`'e doğrudan push edilemez. Seçenekler: (a) ajan için ayrı bir bot hesabı ya da GitHub App (insan onaylar, ajan PR açar; `25320155`'in muafiyeti kaldırılır); (b) onay kuralını kaldırmak. Ayar: Settings → Rules → Rulesets.
2. **Güvenlik raporlama kanalı.** Private vulnerability reporting yalnız public depolarda açılabiliyor (`PUT …/private-vulnerability-reporting` → 404). Depo private kaldıkça SECURITY.md'deki kanal etkin değil; erişimi yalnız ortak çalışanlar var. Depo public yapılınca: Settings → Code security → Private vulnerability reporting → Enable (ya da `gh api -X PUT repos/arknsensei/rootmark/private-vulnerability-reporting`).
3. **Actions dakikaları (private depo).** PR'da zorunlu macOS işi bir koşuda yaklaşık 15 dakika, 10 kat sayılır (~150 dakika) ve hem PR'da hem `main`'e birleştirmeden sonra koşar (birleştirme başına ~300–340 dakika); `verify.yml` haftalık ubuntu'da iki zincir. Ücretsiz planın aylık kotası birkaç PR'la dolabilir. Seçenekler: depoyu public yapmak (Actions ücretsiz), ücretli plan ya da `verify.yml` takvimini seyrekleştirmek.
4. **Açık karar talepleri:** K-GH.5-T (GH-1'in veri kimlikleri: `mdkernel-index/<n>`), K-GH.6-T (Linux'ta dizin yazımı; Linux CI işi bilgi amaçlı).
